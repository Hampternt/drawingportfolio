# Backroom — a hidden-role game for `/drinks`

**Stream:** `claude/secret-hitler-game-jg8xqs`, from `master`, 2026-09-07.
**PR:** Hampternt/drawingportfolio#15.

A fourth game sharing the `/drinks` room shell, alongside Ring of Fire,
3 Man and Last Call. Mechanically this is Secret Hitler (Goat, Wolf &
Cabbage, 2016), re-themed as **Backroom** and built for 5–10 players.

## Scope, as agreed with the owner

- **v1 is the game by itself, drink-free.** A drinking variant ("Secret
  Sippler") comes later as a second mode.
- **Full rules, 5–10 players**: roles and night phase, election with term
  limits and the election tracker, legislative session, all executive
  powers, veto, all four win conditions.
- **A neutral theme behind one seam**, so re-theming is a one-file edit.

## The theme

| Rules term | Backroom |
|---|---|
| Liberal / Fascist | Regulars / Syndicate |
| Hitler | the Boss |
| President / Chancellor | Chair / Second |
| Liberal / Fascist policy | Reform / Racket |
| Ja / Nein | AYE / NAY |
| Election tracker | Heat |
| Investigate Loyalty | Dig Up Dirt |
| Call Special Election | Snap Vote |
| Policy Peek | Read the Room |
| Execution | 86 Them |

All of it is `sh_theme.rs`. Theme text is const data resolved at render
time and never serialized, so a re-theme reaches games already in flight.
`secret_hitler::KIND` is the one string that must never change: it is
persisted in `games.kind`, and renaming it orphans every live row.

## The security finding that shaped the design

`RoomHub` holds one broadcast channel per **room**, never per player, and
`routes::sse_stream` takes **no session extractor**. Every byte published
to a room is therefore readable by anyone who knows the 4-letter code,
including the cookie-less spectator screen at `/room/{code}/screen`.

Consequences, each enforced by a test rather than by care:

1. **`public_view()` never reads a secret field.** `votes` is touched only
   through `.is_some()`, so a ballot laid face-down is public and its value
   is not; `role` only inside the `Phase::Over` gate. Each secret field is
   doc-commented with the test that pins it.
2. **`sh_render.rs` takes `&ShPublicView`, never `&SecretHitlerState`.**
   The signature is the proof; a source sweep fails the build if one
   drifts. `sh_view_data` lives in `sh_routes.rs` and returns the
   projection, so `game.rs` never names the state type either — without
   that, the obvious next edit hands the whole blob to a renderer, since
   `game.rs` already builds view structs inline for 3 Man.
3. **Broadcast fragments are display-only.** No form, no button, no
   `data-show-player`. This is stricter than necessary — a vote button is
   not a secret, and `personalize()` could gate one — but `personalize()`
   only sets `el.hidden`, the markup reaches every subscriber regardless,
   and `screen.html` runs no `personalize()` at all. With controls out
   entirely, "is this fragment safe?" is one line instead of a per-element
   judgement call on every future edit.
4. **Private state is fetched, not pushed.** `GET /room/{code}/sh/private`
   takes `State`, `PlayerSession` and `Path(code)` and nothing else, so no
   request shape can name another player.
5. **`#sh-private` is a sibling of `#game-panel`**, because `swapPanel()`
   replaces that element's innerHTML wholesale.

### The leaderboard is a role oracle — read this before building Secret Sippler

Pours reach `events` → `db::leaderboard` → `RoomMessage::Leaderboard`, over
that same unauthenticated stream. A pour keyed on a hidden fact — "Regulars
drink when a Racket passes", "the Boss drinks when investigated" —
publishes the per-player deltas that partition the table by faction, in
public, on a television, after about one round.

**A pour may key only on a fact already public, or be uniform across all
living seats.** `sh_theme::DrinkEvent` is restricted to exactly that set by
construction: there is no variant for an investigation *result* and none
keyed to a faction. v1's amounts are all zero and the drain is inert.

### Test mode is incompatible with this game

`DRINKS_TEST_MODE=1` exposes `/test/act-as`, which re-issues the caller's
cookie as any room member. For the other three games that is convenience;
for a hidden-role game it is a one-POST role dump. The flag is off by
default and off on the live server, and the existing tests pin the 404.

## Deviations from house style, both deliberate

- **The engine carries a PRNG.** `three_man.rs` takes dice as parameters,
  but Backroom reshuffles at points the caller cannot predict (after an
  enactment, before a draw, before a peek), so passing entropy in would
  mean every handler supplying a seed just in case. `rng_seed` is sampled
  once by the start handler and advanced by a hand-rolled splitmix64, which
  keeps the module a pure deterministic function of its own blob — unit
  tests need no RNG rig — and keeps the `rand` crate out of it. The
  *result* of a shuffle is stored in `draw_pile`, never replayed from the
  seed, so the generator can change without invalidating a live game.
- **Display names are not stored**, resolving per render from
  `db::room_members` (the 3 Man precedent), so a rename via `/account`
  cannot leave a stale name in a live blob. Cost: a rename is retroactive,
  changing the name shown against an old vote too.

## Rules decisions worth remembering

- The tracker resets only when a tile is played **face up**, never on
  election success. Observable only through veto: a government elected at
  Heat 2 that then kills the round fires chaos.
- Chaos grants no power even when the tile fills a slot that prints one,
  clears **both** term-limit records, and still unlocks veto if it is the
  fifth Racket.
- The Snap Vote anchor is the **caller's seat index** — not the snap-elected
  Chair's, not a player id — so rotation resumes to the caller's left and
  survives the caller being thrown out in between. Consumed by a failed
  vote and by a chaos during that round.
- Veto is the tabletop rule (Second proposes, Chair consents), not
  secrethitler.io's simultaneous secret vote.
- 86'ing hides the victim's role until the game ends — the most common
  wrong implementation — and wins for the Regulars if the victim is the
  Boss, at any policy count.
- Dig Up Dirt returns the **party**, so the Boss reads Syndicate, and is
  once per player per game.
- A ballot is final: a seat that has already voted gets `Ok` with no change
  and no `seq` bump. That covers the lossy-phone double-tap; allowing
  changes would let everyone except the last voter revise, which is worse
  than the mis-tap it fixes.
- Dig Up Dirt and Read the Room results persist in the holder's private
  pane for the rest of the game. At a table you would have to remember
  them, but a phone panel repaints on every broadcast, so a result shown
  once would be a result lost. Recorded as a deliberate deviation.
- No house rules shipped: no .io "rebalanced" mode, no secret veto vote, no
  ban on a Syndicate Chair 86'ing the Boss, no revealed roles on death.

## Verification

`./scripts/verify.sh` green. Workspace total **1041 tests** (was 855).

The engine suite includes a soak of **360 randomized full games** across
all six player counts, asserting after every transition that the 17 tiles
are conserved, that neither track overflows, that chaos always resolves
in-band, that an eligible nominee always exists and that roles stay sealed
— and asserting that all four win conditions actually fire across the run,
so an unreachable one fails the build.

Every leak test opens with a **positive control** proving the needle is
findable where it belongs, so a rename cannot quietly make the assertion
vacuous. Two of them caught test bugs rather than implementation bugs
during development, which is the point: the tile test keys on the tile
*class*, because the tile's name is also the public track's label and an
enacted tile is face up and public; and the pairwise privacy test checks
**roles**, because names are public — the nomination picker lists everyone.
