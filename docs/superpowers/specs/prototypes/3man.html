DESIGN DECISIONS
  • Seating is an object, not join order. The TABLE tab reorders it live with ↑/↓ (drunk-proof 44px targets beat drag). Left and right are then unambiguous, and the strip shows the two exposed neighbours on every screen.
  • "Left" is defined out loud — LEFT = next to roll. One label kills the whole argument.
  • One verdict, not a rules quiz. The dice are the smaller element; the sum and "who drinks and why" are the hero. Multiple triggers stack as separate rows (a 3 and a double can both fire).
  • Doubles are a guided flow: pick both dice to one person (they roll two and drink the total) or one die each to two people, send, each victim rolls, and the payback row fires automatically if a matching number comes back.
  • 3 Man is a badge that travels — visible in the top bar, the seat strip, standings and the big screen, reassignable from the TABLE tab.
OPEN QUESTIONS FOR YOU
  • How does the first 3 Man get chosen — first to roll a 3, loser of the last game, or just picked? Right now the opening 3 Man is set by hand in the TABLE tab.
  • Can the 3 Man hand the title straight back to the person who gave it to them, or should the previous holder be locked out for a turn?
  • Does a double of 3s count once or twice against the 3 Man? Currently each 3 counts, so 3+3 is two drinks plus the give-away.
  • Should a gifted die that lands on a 3 / 7 / 9 / 11 trigger those rules too, or only the drink-what-you-roll rule? Currently only the latter.
  • Auto-pass the dice after a verdict, or keep the explicit PASS button? Explicit is safer when phones lag behind the table.
